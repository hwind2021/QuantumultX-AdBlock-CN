# 06 · MITM 与证书配置

MITM（Man-In-The-Middle）是重写规则和 JS 脚本生效的**前提**。
本文讲清楚它是什么、怎么配、以及安全风险。

---

## 一、MITM 到底是什么

### 一句话解释

**MITM 让你自己的设备解密自己的 HTTPS 流量，以便查看和修改内容。**

### 为什么需要它

HTTPS 是加密的。圈 X 虽然能"看到"所有网络请求，
但**看不到加密的内容** —— 它只能知道你访问了 `api.example.com`，
却不知道你传了什么、收到了什么。

```
【不开 MITM】
App ◀──加密的 HTTPS 流量───▶ 服务器
        │
        ▼
    圈 X 只能看到域名，看不到内容
    → 分流规则可用（按域名拦截）
    → 重写规则不可用（无法按 URL 路径匹配）
    → JS 脚本不可用（无法读取响应内容）

【开 MITM】
App ◀──▶ 圈X解密 ◀──▶ 圈X重新加密 ◀──▶ 服务器
              │
              ▼
        圈 X 看到完整内容
        → 分流规则可用
        → 重写规则可用 ✓
        → JS 脚本可用 ✓
```

---

## 二、安全吗

### 关键点：解密发生在你的设备上

```
❌ 错误理解：数据发给某个中间服务器去解密
✅ 正确理解：你的 iPhone 自己解密，数据不离开你的设备
```

圈 X 的 MITM 完全在本机完成：

1. 你在本机生成一张自签名根证书
2. 圈 X 用这张证书，为被 MITM 的域名实时签发站点证书
3. App 信任你的根证书 → 信任圈 X 签发的站点证书 → 解密成功
4. 内容改完后重新加密发往真实服务器

**整个过程没有第三方参与。**

### 真正需要注意的风险

| 风险 | 说明 | 防范 |
|---|---|---|
| **根证书泄露** | 别人拿到你的根证书私钥，就能解密你的流量 | 不要导出/分享证书私钥 |
| **安装来路不明的证书** | 恶意证书可解密你全部流量 | **只安装自己生成的证书** |
| **MITM 范围过大** | 解密范围越广，攻击面越大 | 只把必要域名加入 hostname |
| **越狱设备** | 恶意插件可窃取证书 | 谨慎安装插件 |

> **最重要的一条：绝对不要安装他人提供的证书描述文件。**
> 本项目**只提供 hostname 清单（文本）**，从不提供任何证书文件。
> 如果有人以"去广告"为名让你装证书，请拒绝。

## 三、配置步骤

### 步骤 1 · 生成证书

1. 圈 X → 「**设置**」
2. 找到「**MITM**」并进入
3. 点击「**生成 CA 证书**」
4. 按提示完成生成

### 步骤 2 · 安装并信任证书

生成后会跳转到证书安装界面（或提示你去系统设置）：

1. iOS 「**设置**」→ 顶部出现「**已下载描述文件**」→ 点击进入
2. 右上角「**安装**」→ 输入锁屏密码
3. 安装完成后，**还必须做这一步**：
4. iOS 「设置」→「**通用**」→「**关于本机**」→ 拉到最底部
5. 「**证书信任设置**」→ 找到你的证书 → **打开开关**

> ⚠️ **第 3~5 步极易遗漏。** 只安装不信任，MITM 是不生效的。
> 很多"MITM 配了没反应"的问题都出在这里。

### 步骤 3 · 启用 MITM

回到圈 X → 设置 → MITM → 打开「**启用 MITM**」

### 步骤 4 · 配置 hostname

在 MITM 页面找到「**hostname**」输入框。

**hostname 决定了哪些域名会被解密。** 只有列在这里的域名，
重写规则和脚本才会生效。

本项目的清单在：[`quantumultx/mitm/MITM.list`](../quantumultx/mitm/MITM.list)

#### 配置方法

1. 在浏览器打开上面的 `MITM.list`
2. 复制全部内容（**去掉 `#` 开头的注释行**）
3. 粘贴到圈 X 的 hostname 输入框

#### 使用 %APPEND% 语法

圈 X 默认 hostname 里通常有 `%APPLE%` 之类内置变量。
建议保留默认值，用追加语法：

```
%APPEND%, isub.snssdk.com, sdk.e.qq.com, mobads.baidu.com, ...
```

这样不会覆盖系统预设。

## 四、hostname 配置建议

### 不要做什么

```
❌ hostname = *                      解密全部流量，性能与隐私双重代价
❌ hostname = *.com                  同上，且语法无效
❌ 把银行、支付类 App 的域名加进去     极度危险
```

### 推荐做法

**按需添加，用多少加多少。**

| 你的需求 | 建议 hostname |
|---|---|
| 只去开屏广告 | `MITM.list` 里与开屏 SDK 相关的部分（约 40 条） |
| 开屏 + 信息流 | 完整 `MITM.list`（约 168 条） |
| 自己调试某 App | 只加该 App 的广告域名 |

### 敏感域名务必排除

以下类型**永远不要**加入 hostname：

- 银行 / 证券 App
- 支付类（支付宝、微信支付）
- 政务 / 税务 / 社保
- 企业邮箱 / VPN
- 任何涉及身份证、银行卡信息的服务

本项目已在白名单中排除了这些主域，但你自己添加时要格外小心。

## 五、验证 MITM 是否生效

### 方法一：看证书信息

用 Safari 访问一个被 MITM 的 HTTPS 站点，点地址栏的锁图标，
查看证书颁发者。如果显示的是你生成的 CA 名称，说明生效。

### 方法二：看圈 X 日志

1. 开启 MITM 和一条重写规则
2. 访问对应域名
3. 日志中应出现 `MITM` 或 `REWRITE` 标记

### 方法三：直接看效果

订阅 `AdBlock-Splash.conf`，打开有开屏广告的 App。
如果广告被瞬间跳过（而非等待几秒），说明脚本 + MITM 都正常工作。

## 六、常见问题

### Q：提示"证书不受信任"？

**A：** 没有完成「证书信任设置」这一步。

iOS 安装描述文件 ≠ 信任证书。必须去：
`设置 → 通用 → 关于本机 → 证书信任设置` 手动打开开关。

### Q：MITM 开了但重写规则没效果？

按顺序排查：

1. 证书是否已**信任**（不只是安装）
2. 目标域名是否在 **hostname** 列表中
3. 重写规则的**正则是否匹配**（用 regex101 验证）
4. 分流规则里该域名是否被 `REJECT` 了 —— **被 REJECT 的请求走不到重写阶段**

> 第 4 点很容易踩坑：分流在连接层拒绝，重写需要连接建立后解密。
> 所以**同一个域名不要既在分流里 REJECT，又在重写里处理**。

### Q：开启 MITM 后耗电明显增加？

正常现象。解密是 CPU 密集操作。缓解办法：

1. 精简 hostname 列表
2. 减少重写规则数量
3. 不需要时关闭 MITM

### Q：某些 App 检测到 MITM 后拒绝联网？

这是**证书绑定（Certificate Pinning）**，多见于银行、金融类 App。

解决办法：把这些 App 的域名从 hostname 中移除。
**这类 App 本来就不该被 MITM。**

### Q：MITM 会影响 VPN / 代理功能吗？

不会冲突，但会叠加开销。MITM 是在代理链路之上额外做的解密。

## 七、不开启 MITM 的替代方案

如果你因为安全顾虑不想开 MITM，仍然可以用：

**分流规则**（`Splash-Killer` + `BlockHttpDNS` + `AdBlock-Lite`）

这是完全不需要 MITM 的方案，能解决大部分开屏广告，
代价是会有 1.5~5 秒的等待超时。
