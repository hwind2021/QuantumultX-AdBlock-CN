# 07 · 常见问题排查

按现象分类，从最常见的开始。

---

## 一、广告没被去掉

### 现象 1：所有 App 的开屏广告都还在

**排查顺序：**

```
① 分流规则是否已启用？
   圈 X → 分流 → 确认开关是绿色

② 规则文件是否下载成功？
   配置文件里点开该规则，看是否有内容、条数是否正常

③ 是否订阅了 BlockHttpDNS？
   没装这层，国内 App 的拦截率会大幅下降

④ 圈 X 是否处于开启状态？
   首页顶部 VPN 开关是否连接
```

**验证方法：**

打开一个已知有广告的 App，然后看日志：

```
圈 X → 首页 → 右上角日志图标
```

如果什么都看不到，说明圈 X 没有接管流量。
如果看到大量 REJECT 记录但广告还在，跳到「现象 3」。

---

### 现象 2：部分 App 有效，部分无效

这通常是**该 App 的广告 SDK 未被覆盖**。

**自查步骤：**

1. 圈 X 设置 → 开启「记录网络活动」
2. 彻底杀掉该 App，重新打开
3. 查看日志中启动瞬间的请求
4. 找出可疑的广告域名

**识别特征：**

| 特征 | 示例 |
|---|---|
| 域名含广告关键词 | `pangolin`、`gdt`、`mobads`、`tanx`、`adservice`、`adsdk` |
| 启动首秒集中出现 | 打开 App 时密集爆发 |
| 路径含广告语义 | `/splash`、`/launch`、`/ad/list`、`/getAd` |

确认后加入自定义规则，并欢迎提 Issue 告诉我们，让所有人受益。

---

### 现象 3：日志里能看到 REJECT，但广告照样展示

三种可能：

**① 广告素材被预缓存**

App 上次使用时就下载好了下次的开屏素材，断网也能展示。

> 解决：清除该 App 缓存，或重装 App。之后规则就能拦住新的请求。
> 这类广告无法彻底根治，只能缓解。

**② 走了 IP 直连**

HTTPDNS 拦截未生效。检查 `BlockHttpDNS.list` 是否已启用。

**③ 广告与业务共用域名**

比如某 App 开屏走 `api.xxx.com/ad/splash`，而该域名承载登录、内容。
这种我们**不敢**用分流规则拦（会搞坏 App），只能用重写规则按路径匹配。

> 解决：确认该域名是否在 MITM hostname 中，然后订阅重写规则。

---

### 现象 4：广告没了，但卡在启动页好几秒

这是**等待 SDK 超时**的典型表现，说明分流规则生效了，但走的是 REJECT 而非脚本。

> 解决：开启 MITM，订阅重写规则 + 安装 JS 脚本。
> 脚本会让 App 收到"无广告"的空响应，瞬间跳过。
> 详见 [05-JS脚本使用教程](05-JS脚本使用教程.md)。

## 二、App 出问题

### 现象 5：某个 App 打不开 / 白屏 / 一直转圈

**立刻止损：**

```
圈 X → 分流 → 依次关闭刚添加的规则 → 每关一条就打开 App 测试
```

定位到具体规则后，处理办法见下方「如何放行」。

**如何为单个域名放行：**

圈 X 没有内置白名单，利用**规则从上到下、命中即停止**的特性：

1. 新建本地 `.list`，第一行写放行规则：

```
HOST-SUFFIX,api.xxx.com,DIRECT
```

2. 在「分流」列表里，把这条**拖到拦截规则上方**

> 注意用 `DIRECT` 而不是 `REJECT`。`DIRECT` 表示直连放行。

---

### 现象 6：微信 / 支付宝等支付功能异常

**大概率是 MITM hostname 包含了支付域名。**

立即检查：圈 X → 设置 → MITM → hostname

**必须移除**以下类型：

```
alipay.com / alipayobjects.com
tenpay.com / weixin.qq.com
unionpay.com / 95516.com
各银行域名
```

> 本项目已在白名单中排除这些主域，但如果你自己添加过 hostname，请检查。

---

### 现象 7：App Store 下载变慢或失败

Apple 相关域名被误拦。

检查是否订阅了过于激进的规则（如 `AdBlock-Full`）。
在白名单中确保包含：

```
apple.com / icloud.com / mzstatic.com / apple-cloudkit.com
```

本项目的 `whitelist.txt` 已包含这些，若仍有问题请提 Issue。

---

### 现象 8：推送收不到

`push.apple.com` 相关域名被拦截。

本项目白名单已包含 `apple.com`，正常情况下不会误伤。
如果问题依旧，检查是否使用了其他第三方规则集。

## 三、规则与配置问题

### 现象 9：规则文件下载失败

**可能原因与解决：**

| 原因 | 解决 |
|---|---|
| 网络无法访问 GitHub raw | 改用镜像地址，见 [08 文档](08-规则订阅与每日更新.md) |
| URL 填写错误 | 对照 README 重新复制 |
| 文件过大，超时 | `AdBlock-Full` 约 29 万条，建议改用 Lite |
| GitHub 限流 | 稍后重试 |

---

### 现象 10：规则显示已下载，但条数为 0

文件为空或格式错误。

**检查：** 用浏览器打开你填的 URL，看是否有内容。

**常见坑：** 复制 URL 时多带了空格或换行。

---

### 现象 11：重写规则完全没反应

按顺序排查：

```
① MITM 是否开启？
② 证书是否已"信任"（不只是安装）？
   设置 → 通用 → 关于本机 → 证书信任设置
③ 目标域名是否在 hostname 列表中？
④ 该域名是否在分流规则里被 REJECT 了？
   ← 被 REJECT 的请求走不到重写阶段，这个坑很常见
⑤ 正则是否匹配？用 regex101.com 验证
```

---

### 现象 12：脚本没触发

```
① 脚本名称是否与重写规则中引用的一致？
② 脚本是否已保存且无语法错误？
③ 域名是否在 MITM hostname 中？
④ 把脚本的 debug 改成 true，看是否弹通知
```

## 四、性能与耗电

### 现象 13：开启后网络变慢

**原因与解决：**

| 原因 | 解决 |
|---|---|
| 订阅了 `AdBlock-Full`（29 万条） | 改用 `AdBlock-Lite` |
| MITM hostname 过多 | 精简列表 |
| 同时订阅了重复规则 | Lite 与 Full 二选一 |
| 大量 `HOST-KEYWORD` 规则 | 本项目已限制在 29 条，检查是否用了其他规则集 |

---

### 现象 14：耗电明显增加

MITM 解密是 CPU 密集操作，耗电增加属正常。

**缓解：**

1. 不需要时关闭 MITM（分流规则仍生效）
2. 精简 hostname
3. 减少同时启用的重写规则

## 五、获取帮助

### 提 Issue 前请准备

请提供以下信息，否则难以定位：

```
1. 圈 X 版本
2. iOS 版本与机型
3. 订阅了哪些规则文件
4. 是否开启 MITM
5. 出问题的 App 名称与版本
6. 圈 X 日志截图（关键部分）
```

### 提交新规则

如果你发现了新的开屏广告域名，欢迎提 PR：

编辑 [`tools/data/splash_sdk.conf`](../tools/data/splash_sdk.conf)，
在对应分类下添加，格式：

```
HOST-SUFFIX,新域名
```

或提 Issue，我们会验证后加入。

### 提交误杀反馈

如果本规则导致某个 App 功能异常，提 Issue 时请注明：

```
- App 名称
- 具体异常表现
- 你订阅了哪些规则
- 该 App 涉及的关键域名（如已知）
```

我们会把它加入白名单。

## 六、快速自查清单

遇到任何问题，先过一遍这个清单：

```
□ 圈 X VPN 已连接？
□ 分流规则开关是绿色？
□ 规则文件有实际内容（非 0 条）？
□ BlockHttpDNS 是否已订阅？
□ 是否重启过 App 测试？
□ （如用重写）MITM 已开启？
□ （如用重写）证书已信任？
□ （如用重写）域名在 hostname 中？
□ （如用重写）该域名没被分流 REJECT？
□ 是否订阅了重复或过大的规则？
```
